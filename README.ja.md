# dejavu（デジャブ）

**Claude に「記憶」を持たせるためのツールです。**

Claude と一緒に作業をしていると、その場では話がどんどん進みます。ところが、ウィンドウを閉じて翌日また開くと、Claude は前日のやりとりを何ひとつ憶えていません。同じ説明をもう一度することになり、同じ調べ物をもう一度させることになります。

dejavu は、Claude が調べたことや決めたことをあなたのパソコンの中に書き留めておき、次に必要になったときに読み戻すためのツールです。これがあると、Claude は「昨日の続き」から話を始められるようになります。

さらに dejavu は、**Obsidian**（無料のメモアプリ）と組み合わせて使えます。組み合わせると、Claude が憶えた内容をあなた自身も普通のメモとして読み返せるようになり、加えて、ターミナル・Claude デスクトップのチャット・Cowork・Xcode という**どの入り口から話しかけても同じ知識が使える**ようになります。  
またオプション機能として、Obsidianのvault内のメモの内容を読んで、自動的に相互リンクさせることも可能です。

保存されるものはすべて、あなたのパソコンの中だけに置かれます。外部のサーバーに送信されることはなく、アカウント登録も不要で、料金もかかりません。

## 何を解決するのか

まず、dejavu がどんな困りごとを解決するツールなのかを見ていきましょう。
思い当たる場面があれば、dejavu が役に立ちます。

### 場面1 ： 翌日、話が振り出しに戻る

ある日、Claude と何時間もかけて調べ物をしたとします。Claude は資料やコードを次々に開き「なぜこうなっているのか」を突き止め、あなたと一緒に方針を決めます。かなり前に進みました。その日はそこで終わりにしてウィンドウを閉じます。

翌朝、新しく Claude に話しかけます。ところが Claude は昨日のことを**何ひとつ憶えていません**。同じ資料をもう一度開き、同じ手順をもう一度たどり、同じ時間をかけて昨日とまったく同じ結論にたどり着きます。あなたは前提の説明からやり直すことになります。

### 場面2 ： 長い会話の途中で、続きを別の場所に移せない

会話が長くなると Claude の答えの質はだんだん落ちていきます。新しい会話に移ったほうが良いのですが、移った瞬間に、それまで積み上げた前提がすべて消えます。結局、長くなった会話を我慢して使い続けるか、また一から説明し直すかの二択になります。

### 場面3 ： 半年前に調べたことを、また調べている

「前にも同じことを調べた気がする」——けれど、どこに書いたか思い出せない。あるいは、そもそもどこにも書いていない。結局、同じ調査をもう一度やることになります。

### dejavu がすること

これらはすべて、**Claude に残る記憶が少ない**ことが原因です。

dejavu は Claude が学んだことを書き留めておく場所を、あなたのパソコンの中に用意します。Claude は作業しながらそこに自動的に書き込み、次に必要になったときに自動的に読み出します。

```
1日目                            2日目
────────                        ────────
Claude が調べる                  あなた 「昨日の続きから」
Claude が分かる                  Claude が書き留めを読む
Claude が書き留める              Claude が昨日の続きから再開する
      │                                    ▲
      └────────── .dejavu/ ────────────────┘
              （パソコンの中の保管場所）
```

## dejavu が憶えてくれること

前の節では、Claude に記憶が残らないという問題を説明しました。ここでは、dejavu を入れると具体的に何ができるようになるのかを見ていきます。

dejavu が憶えるのは、おおまかに次の4種類です。

| 種類 | 中身の例 |
| --- | --- |
| **作業の続き** | 「昨日はここまで終わった。次はこの作業から」 |
| **調べて分かったこと** | 「この機能はこういう仕組みで動いている」 |
| **決めたこと** | 「A案ではなくB案を選んだ。理由はこれこれ」 |
| **あとでやること** | 「あの不具合は今日は触らない。あとで直す」 |

そして、これらを使ってこんなことができるようになります。

```
あなた:  昨日の続きから

Claude:  昨日は資料の整理を途中まで進めて、第3章のところで止まっていますね。
         次は参考文献の確認から、という話でした。続けますか？
```

```
あなた:  最近なにやってたっけ

Claude:  直近3日だと、月曜に方針を決めて、火曜に下書きを作って、
         水曜は不具合の調査をしていました。
```

### コマンドを覚える必要はありません

ここが dejavu の一番の特徴です。**あなたが dejavu のコマンドを打つ場面は、ほとんどありません。**

いつ書き留めるか、いつ読み戻すかは、会話の流れから Claude が自分で判断します。あなたは普段どおり話しかけるだけです。実際のところ、意識して言う必要があるのは次の5つくらいです。

| こう言うと | Claude はこうします |
| --- | --- |
| 「昨日の続きから」 | 前回の書き留めを読んで、続きから再開する |
| 「ここまでの経緯をメモして」 | 別のチャット（セッション）のために、今のチャットの内容を憶える |
| 「今日の分を保存して」 | 次回のために、今日の内容を書き留める |
| 「あとでやるから憶えといて」 | 手を止めずに、メモだけ残す |
| 「最近なにやってたっけ」 | 直近の作業をまとめて報告する |

## Claude 自身の記憶機能との違い

「Claude Code にも記憶の仕組み（`CLAUDE.md` や `MEMORY.md`）があるのでは?」
—— あります。そして**dejavuとは競合しません。役割が違うので、両方使うのが正解です。**

Claude Code が持っているのは、机の上に開きっぱなしにしておく**メモ帳**です。会話の最初に自動で開かれるので、設定なしですぐ読み書きできます。ただしメモ帳は薄く、**書ける量に上限があり、溜まった内容を探す手段もありません。** 書き込みが増えるほど、古いページは押し出されて埋もれていきます。

dejavu は、いわば**日記**です。その日やったこと、決めたこと、次にやることを、日付とともに書き留めていきます。そして「昨日の続きから」と言われたときに、その日のページを開きます。**毎回ぜんぶ読み返すわけではないので、何冊たまっても会話が重くなりません。** 半年前のページも、探せばちゃんと出てきます。

もうひとつの違いは**届く範囲**です。Claude Code のメモ帳はそのパソコンの Claude Code専用で、チャットや Cowork からは見えません。しかしdejavuを使うことで、どの入り口からでも同じ日記を読み書きできるようになります。

| | Claude 自身の記憶 | dejavu |
| --- | --- | --- |
| たとえるなら | **手元の薄いメモ帳** | **日記・日報** |
| 得意なこと | 設定なしですぐ効く | 探して引き出せる |
| 量が増えると | 上限を超えた分は埋もれる。無くなる | 増えても埋もれない |
| 使える場所 | Claude Code だけ | すべての入り口 |

正直に言うと、**メモがまだ少なくて、案件が1つで、Claude Code しか使わないなら、
Claude 自身の記憶だけで足ります。** dejavu が効いてくるのは、知識が溜まってきてからです。

> 仕組みの詳細（`CLAUDE.md` と自動メモリの役割分担、読み込み量の上限、
> claude.ai のメモリとの関係）は [REFERENCE.ja.md](docs/REFERENCE.ja.md) にまとめてあります。

## Obsidian を組み合わせると変わること

ここまでに説明した機能は、**dejavu だけを入れれば全部使えます。**
Obsidian は必須ではありません。

ただし、dejavu だけだと、2つ物足りない点が残ります。

- **書き留めた内容を、あなた自身が読めない。** dejavuの情報の保管場所はデータベースという形式なので、Claude は読み書きできますが、あなたが開いて読むことはできません
- **Claude デスクトップのチャットからは使えない。** 詳しくは後述しますが、チャットにはパソコンの中のファイルを見る手段が無いためです

Obsidian を組み合わせると、この2つが解決します。

### そもそも Obsidian とは

[Obsidian](https://obsidian.md) は無料のメモアプリです。特徴は、メモが**特殊な形式ではなく、ただの文章ファイル（Markdown）としてパソコンの中に置かれる**ことです。

メモをまとめて置いておくフォルダのことを、Obsidian では **vault（ボールト）** と呼びます。中身はただのフォルダで、その中に文章ファイルが並んでいるだけです。

### 3つの記憶の関係

前の節で、Claude 自身の記憶を**メモ帳**、dejavu を**日記**にたとえました。その並びで言うと、Obsidian は**本棚に並べた書類**にあたります。

日記が「いつ何をしたか」の記録なのに対して、書類は**何度も引くことになる知識**です。分野ごとに整理されていて、案件が終わっても本棚に残り、何年たっても引き出せます。そして決定的な違いとして、**あなた自身が手に取って読むことができます。**

| | Claude 自身の記憶 | dejavu | Obsidian |
| --- | --- | --- | --- |
| たとえるなら | **手元のメモ帳** | **日記・日報** | **本棚に並べた書類** |
| 何が書かれるか | いま気づいたこと | その日やったこと・決めたこと | 何度も引く知識・あなた自身の情報 |
| いつ読まれるか | 毎回、自動で | その案件の話をするとき | 案件を問わず、関係しそうなとき |
| どれくらい残るか | 増えると押し出される | その案件が続くあいだ | ずっと残る |
| **あなたが読めるか** | 読めない | 読めない | **読める** |
| 使える場所 | Claude Code だけ | すべての入り口 | すべての入り口 |

### dejavuの役割

手帳と日記と本棚は、3つとも役割が違うので、置き換えるのではなく**重ねて使います。**  
ClaudeとObsidianそれぞれの不便な点を補完するのがdejavuで、dejavuに情報を渡すと、自動的に日記と本棚に適切に分けながら書き込んでくれます。

### 変わること1 ： 憶えた内容を、自分でも読み返せる

dejavu が Obsidian に書き込むと、書き留めた内容がそのまま文章ファイル（ただのテキスト）になります。つまり、**Claude が憶えたことが、そのままあなたのメモになります。**

Obsidian を開けば読めますし、検索もできますし、メモ同士にリンクを張ることもできます。iPhone の Obsidian アプリからも読めます。「Claude が何を憶えているか分からない」という不安がなくなり、間違って憶えていたら文章を直すことができます。

### 変わること2 ： どの入り口からでも、同じ知識が使える

Claude にはいくつもの入り口があります。ターミナルの Claude Code、Claude デスクトップのチャット、Cowork、Xcode に組み込まれた Claude Agents ——どれも同じ Claude ですが、できることは少しずつ違います。

**Obsidian の vault はただのフォルダなので、ファイルを読める入り口なら直接読めます。** ターミナルの Claude Code と Xcode の Claude Agents がこれにあたります。しかし、**Claude デスクトップのチャットにはファイルを読む機能がありません。** また Cowork はObsidianデータを読めますが、使うたびにフォルダを手作業で繋ぎ直す必要があります。

ここを dejavu が補完します。dejavu はすでに、この4つのアクセス方法すべてから使えるように作られています。そこで、**dejavu に vault の場所を教えておけば、dejavu が代わりに vault を読み書きしてくれます。** その結果、どの入り口からでも同じメモが使えるようになります。

| | ターミナル | Xcode | デスクトップのチャット | Cowork |
| --- | :-: | :-: | :-: | :-: |
| Obsidian だけを使う場合 | ✅ | ✅ | ❌ 使えない | △ 毎回フォルダを繋ぐ |
| **dejavu 経由で使う場合** | ✅ | ✅ | ✅ | ✅ |

## 何をどこに置くか

Obsidian を繋ぐと、書き留める場所が2か所になります。そうなると「この内容はどちらに入れるのか」という判断が必要になります。この節では、その振り分け方を説明します。

考え方はとてもシンプルです。

> **dejavu は「その案件（プロジェクト）のこと」を憶える。Obsidian は「あなたのこと」を憶える。**

日記は案件ごとに1冊、本棚は案件をまたいで1つ。そう考えると迷いにくくなります。

具体的には次のように分かれます。

| 置き場 | 何が入るか | 例 |
| --- | --- | --- |
| `.dejavu/`（案件のフォルダの中） | **その案件だけの話** | 「昨日はここまで」「次はこの不具合」 |
| `docs/knowledge/` | その案件の話で、**チームと共有したいもの** | 「この機能はこう使う決まり」 |
| Obsidian の `Knowledge/` | **どの案件でも通じる知識** | 「この書き方には落とし穴がある」 |
| Obsidian の `UserInfo/` | **あなた自身の情報** | 経歴、好み、仕事の進め方 |
| Obsidian の `Research/` | **調べて分かったこと** | 「A と B を比較した結果」 |

迷ったときの判断基準は、ひとつ覚えておけば足ります。

> **「別の案件でも、同じことが言えるか？」**  
> 言えるなら Obsidian。この案件でしか通じない話なら dejavu。

### 振り分けるのは Claude です

とはいえ、毎回この判断をあなたがするわけではありません。**振り分けは Claude が判断します。** 振り分けに迷った時には、あなたに問い合わせます。

```
Claude:  いま分かったことですが、これはこの案件だけの話ではなく、
         一般的に当てはまる内容だと思います。
         共通の知識として Obsidian に保存しておきますか？

         1. はい   2. いいえ   3. 今後は聞かずに保存して   4. 今後は保存しなくていい
```

3番か4番を選ぶと、それ以降は聞かれなくなります。あとから設定を戻すこともできます。

## 使うとこうなる

ここまでの説明を、実際の会話の形で見てみましょう。コードを書く人と、書かない人の両方の例を挙げます。

### エンジニアの場合

**朝、作業を再開するとき**

```
あなた:  昨日の続きから
```

> 昨日は認識モジュールの分離を Phase 4e まで終わらせて、Phase 5 は後日にしていますね。変更したのは `FoodAnalysisService.swift` と `GIService.swift` です。続けますか？

**作業中、不具合を直したあと**

> 直りました。原因は `ignoresSafeArea()` の内側では `safeAreaInsets` が 0 になることでした。
>
> これはこのアプリ特有の話ではなく、SwiftUI 全般に当てはまる内容です。共通の知識として Obsidian に保存しておきますか？

**半年後、まったく別のアプリを作っているとき**

```
あなた:  ここのレイアウトが下にズレる
```

> 以前、同じ問題を踏んでいます。`ignoresSafeArea()` の内側では `safeAreaInsets` が 0 になる、というメモが Obsidian の `Knowledge/` に残っています。同じ対処で直るはずです。

案件が変わっても知識が付いてくるので、**同じ調査を二度やらずに済みます。** 半年前の自分が調べたことを、半年後の自分が受け取れるという状態になります。

**チームに渡したいとき**

`docs/knowledge/` フォルダに文章ファイルとして置けば、git で他のメンバーにも共有されます。置き場所を変えても dejavu は同じように検索できるので、使い勝手は変わりません。

### エンジニアでない場合

コードを書かない人でも使えます。案件のフォルダを用意する必要はなく、Obsidian だけを繋いだ形で使います。

**調べ物をする仕事の場合**

```
あなた:  先週調べた助成金の条件、もう一回教えて

Claude:  Obsidian の Research/ に残っています。7月20日に調べたときの結論は、
         対象は従業員50人以下、申請期限は9月末、必要書類は3種類、でした。
```

**文章を書く仕事の場合**

```
あなた:  この原稿、いつもの調子で直して

Claude:  UserInfo/ に文体のメモがありました。
         一文を短くする、体言止めを避ける、専門用語には必ず言い換えを添える。
         この方針で直します。
```

やることは、コードを書く人の場合とまったく同じです。**「これは憶えておいて」と言うだけ**で、次に聞いたときに出てきます。そして出てきた内容は、Obsidian を開けばあなた自身の目でも確認できます。

## インストール

作業は最大で5つです。上から順に進めてください。所要時間は10分ほどです
（5 まで行う場合は、モデルのダウンロードでもう少しかかります）。

| | 作業 | 必要な人 |
| --- | --- | --- |
| 1 | dejavu を入れる | **全員** |
| 2 | Obsidian を繋ぐ | 任意（おすすめ） |
| 3 | Claude デスクトップから使えるようにする | チャットや Cowork を使う人 |
| 4 | 案件のフォルダに導入する | コードを書く人 |
| 5 | メモ同士を自動でつなぐ | 任意（Ollama が必要） |

### 1. dejavu を入れる

Mac の「ターミナル.app」を開いて、次の2行をコピーして貼り付け、それぞれ Enter を押します。

```bash
brew install alohayos/tap/dejavu
dejavu init --global
```

1行目で dejavu 本体が入ります。2行目で、Claude に「dejavu の使い方」を教え込みます。どちらも最初の1回だけで、あとは実行する必要はありません。

> - [Homebrew](https://brew.sh) が入っていない場合は、先にインストールしてください
> - `dejavu` の代わりに、短い `deja` と打っても同じように動きます
> - 新しいバージョンに上げたくなったら `brew upgrade dejavu` でアップデートできます

### 2. Obsidian を繋ぐ（任意）

Obsidian を使ったことが無くても大丈夫です。無料ですし、前に書いたとおり vault はただのフォルダです。

まず Obsidian 本体を用意します。

1. <https://obsidian.md/download> からダウンロードしてインストールします
2. 起動して **Create new vault**（新しい vault を作る）を選びます
3. 名前と保存先を決めます。迷ったら、名前は `MyVault`、保存先は「書類」フォルダで
   構いません（→ [公式の手引き](https://help.obsidian.md/vault)）

次に、作った vault の場所を dejavu に教えます。ターミナルに戻って、次の2行を実行します。  
`~/Documents/MyVault` の部分は、手順3で決めた保存先に置き換えてください。

```bash
dejavu obsidian init ~/Documents/MyVault
dejavu obsidian doctor
```

2行目の `doctor` は、いまの状態を点検して表示するコマンドです。vault の場所と、これからどのように書き込むかが表示されれば成功です。

このとき、vault の中に `Knowledge/` `UserInfo/` `Research/` という3つのフォルダが作られます（すでにあれば作りません）。**それ以外には一切手を加えません。**

#### 保存先がパソコン内かクラウドかによって、書き込み方が変わります

| vault の保存先 | スマホから読めるか | dejavu の書き込み方 |
| --- | :-: | --- |
| パソコンの中のフォルダ | 読めない | 新規作成・追記・**書き換え** |
| iCloud / Dropbox / Google Drive / Obsidian Sync | 読める | 新規作成・追記のみ |

どちらの状況にあたるかは dejavu が自動で判定します。判定結果とその理由は`dejavu obsidian doctor` がいつでも表示してくれます。

### 3. Claude デスクトップから使えるようにする

チャットや Cowork から dejavu を使いたい場合は、次の1行を実行します。

```bash
dejavu install-mcp
```

実行したあと Claude デスクトップを一度終了して、開き直してください。
それでチャットと Cowork から使えるようになります。

### 4. プロジェクトのフォルダに導入する

プロジェクトのフォルダ（リポジトリ）上で、次の2行を実行します。

```bash
cd ~/your-project
dejavu init
```

`.dejavu/` というフォルダが作られ、`CLAUDE.md` と `.gitignore` にそれぞれ1行だけ
追記されます。**あなたのソースコードには一切触りません。** すでに開発中のプロジェクトでも
安全ですし、間違って2回実行しても問題は起きません。

プロジェクトごとに実行することで、そのプロジェクトの日記が作成されます。

### 5. メモ同士を自動でつなぐ（任意）

dejavu が Obsidian にメモを書いたとき、**内容の近い過去のメモへのリンクを自動で付ける**
機能です。「これ、前にも似たことを調べた気がする」に、探しに行かなくても気づけるように
なります。

使うには、パソコンの中で動く AI（[Ollama](https://ollama.com)）が必要です。
**入れなくても、ここまでの内容はすべて動きます。**

1. <https://ollama.com/download> から Ollama をインストールして、起動します
2. ターミナルで次の3行を実行します

```bash
ollama pull bge-m3
dejavu config relate embed
dejavu obsidian relate --backfill
```

上から順に、文章を読む担当のモデルを取り込み、それを使うよう dejavu に伝え、いま vault に
あるメモを読み込ませています。3行目だけ数分かかることがあります。

これで完了です。以降、メモが書かれるたびにリンクが自動で付きます。

- 動いているか確認する → `dejavu obsidian doctor`
- **Ollama を止めているときは、リンクだけが後回しになります。** メモはいつもどおり
  保存され、次に Ollama が動いたときにリンクが付きます。すぐ付けたいときは
  `dejavu obsidian relate --start`（止まっていれば、確認のうえ起動します）
- やめる → `dejavu config relate off`（すでに付いたリンクは残ります）
- 文章がパソコンの外に出ることはありません

細かい設定は
[REFERENCE](docs/REFERENCE.ja.md#メモ同士の自動リンクollama)にまとめてあります。

## 入り口ごとの使い方

インストールが終わったら、どの入り口から話しかけても同じ知識が使えます。
ただし入り口によって少しだけ勝手が違うので、順に説明します。

### Claude デスクトップ — チャット

チャットにはパソコンのファイルを読む機能がありませんが、インストール手順3を済ませて
あれば、dejavu が代わりに読み書きしてくれます。

```
あなた:  ボクのプロフィールをもとに、登壇者の紹介文を200字で書いて

Claude:  （Obsidian の UserInfo/Profile.md を読んで）
         1998年、Apple Newton MessagePad 向けに日本語入力を開発。……
```

```
あなた:  この方針、今後どこでも憶えておいて

Claude:  Obsidian の Knowledge/ に保存しました。
         別のチャットからでも、Cowork からでも出てきます。
```

> **どの案件の話かは「プロジェクトAについて、議事録をまとめてほしい」などのように案件名を言葉で伝えてください。** チャットと Cowork は「いまどのフォルダで作業しているか」を知る手段がありません。案件名を出さないと、あなた個人の知識とObsidian の内容だけが使われます。

### Claude デスクトップ — Cowork

チャットと同じ仕組みを使うので、**Obsidian のフォルダを手作業でCoworkに繋ぐ必要がありません。**

```
あなた:  この案件、いまどこまで進んでる？

Claude:  （案件の記録を見て、続けて Obsidian の Research/ も見て）
         直近は Phase 4e まで完了、Phase 5 は後日、となっています。
         関連して、7月17日に計測した記録も残っています。
```

### Claude デスクトップ — Code

パソコンのファイルを直接読めるので、ターミナルの Claude Code とまったく同じように動きます。特別な設定は要りません。

### ターミナルの Claude Code

案件のフォルダに移動して、いつもどおり起動するだけです。

```bash
cd ~/your-project
claude
```

あとは普通に話しかけてください。書き留めるのも読み戻すのも Claude が判断します。意識して言うのは、前に挙げた5つの言い方くらいです。

### Xcode の Claude Agents

Xcode 26 以降に組み込まれている Claude Agent も、ターミナルと同じようにファイルを読めるので、そのまま使えます。案件の `CLAUDE.md` が自動的に読まれるため、手順4の `dejavu init` さえ済ませてあれば、追加の設定は要りません。

> まれに `dejavu: command not found` と表示されることがあります。Xcode が起動する環境の都合で、dejavu の場所が見つからないためです。対処法は [REFERENCE.ja.md](docs/REFERENCE.ja.md) に書きました。

## すでに Obsidian を使っている人へ

すでに Obsidian を使っている方は、「いま持っているメモが荒らされないか」が気になると思います。心配される点は3つあると思いますので、順に説明します。

### 1. 既存のメモは変更されません

**あなたが書いたメモは、1つも変更されません。**

dejavu が作ったメモには、ファイルの先頭に `source: dejavu` という印が付きます。**この印が無いメモは、dejavu にとって永久に読み取り専用です。** 追記もしませんし、書き換えもしません。

仮に dejavu が書き込もうとしても、次のようにエラー表示されて止まります。

```
error: 手書きのメモ.md was not written by dejavu
       (no `source: dejavu` in its frontmatter).
       Notes you wrote by hand are never modified.
```

### 2. フォルダ構成は、あなたのやり方のままで構いません

`Knowledge/` フォルダは、最初は何も入っていない状態です。PARA でも Zettelkasten でもJohnny.Decimal でも、あなたの流儀でサブフォルダを作ってください。

dejavu は、**すでにあるフォルダに入れるだけで、自分で新しいフォルダを作りません。** 分類の情報はメモの先頭にも書き込まれるので、あとからフォルダを組み替えても、検索や分類が壊れることはありません。

### 3. 見せる範囲を選べます

指定したフォルダ以外は、そもそも読み込まれません。既定では `Knowledge/` `UserInfo/` `Research/` の3つだけです。個人的な日記や旅行のメモが、仕事中に突然出てくることはありません。

すでに使っているフォルダ名に合わせたい場合は、次のように変更できます。

```bash
dejavu config userinfo_dir Profile     # UserInfo/ ではなく Profile/ を使う
```

## よくある質問

**保存を忘れそうです**  
Claude が作業しながら自動で保存するので、基本的に気にしなくて大丈夫です。ひとつだけ習慣にする価値があるのは、作業を終えるときに「今日の分を保存して」と言うことです。これが翌朝の「昨日の続きから」を成立させます。

**書いた内容はどこかに送信されますか？**  
されません。dejavu が外部と通信することはありませんし、アカウント登録も不要です。[メモ同士を自動でつなぐ機能](#5-メモ同士を自動でつなぐ任意)を有効にした場合も、文章が渡るのは同じパソコンの中で動いている Ollama だけです。

**Claude が遅くなりませんか？**  
むしろ速くなります。検索は数十ミリ秒で終わりますし、Claude が何ファイルも読み直す手間が省けます。毎回読み込まれる指示文も40行ほどです。

**Claude が間違った内容を憶えてしまったら？**  
「そのメモは間違っているから直して」と言えば直します。丸ごと消したい場合は `dejavu rm <uid>` です（uid は、検索結果の角括弧の中に出てくる短い文字列です）。

**案件側と Obsidian 側で内容が食い違ったらどうなりますか？**  
両方をまとめて表示して、どちらを採用するかあなたに聞きます。dejavu が勝手に決めることはありません。Obsidian 側を間違った内容で上書きしてしまうと、その間違いが他のすべての案件に付いて回ってしまうからです。

**日本語で使えますか？**  
使えます。「検索」「認証」のような**2文字の日本語**は多くの検索の仕組みが取りこぼしますが、dejavu はそこを確実に拾えるように作ってあります。

**Obsidian は必ず必要ですか？**  
いいえ。dejavu だけで完結します。Obsidian を繋ぐと、憶えた内容を自分で読み返せるようになり、チャットや Cowork からも同じ知識が使えるようになります。また、多くの知識を保存することができるようになります。

**プログラムを書かない人でも使えますか？**  
使えます。手順1と2だけで（必要なら3も）、あなた個人の知識の保管場所として成立します。手順4は不要です。

**Claude Code の自動メモリ（MEMORY.md）があるのに必要ですか？**  
役割が違うので併用します。Claude 自身の記憶は手軽ですが、読み込まれる量に上限があり、検索もできません。dejavu は普段は読み込まず検索で引き出すので、知識が増えても効き続けます。詳しくは [Claude 自身の記憶機能との違い](#claude-自身の記憶機能との違い) を読んでください。

**Claude Code 以外からも使えますか？**  
使えます。普通のCLIコマンドとして `dejavu add` や `dejavu search` を手で打てます。ただ、AI に運転させることを前提に作ってあるので、そこで一番力を発揮します。

**あとでやめたくなったら？**  
案件のフォルダからは `.dejavu/` を削除して、`CLAUDE.md` に追記された1行を消すだけです。それ以外の場所には何も残していません。Obsidian のメモはただの文章ファイルなので、そのまま手元に残ります。

## 付録 ： 手持ちの資料をまとめてつなぐ

「メモ同士を自動でつなぐ」で書いたように、dejavuはObsidianに保存したメモを自動的に他のメモと知識リンクすることができます。でもdejavuが管理していないメモについてはリンクを作りません。これは利用者のObsidianメモを勝手に書き換えないように保護しているからです。

しかし、こんな要望もあるでしょう。
> パソコンにある資料を全てObsidianへ取り込んで、知識リンクを作りたい。でもリンクを作る作業をAIにやらせると、プライベートな情報が外部AIに読まれてしまう。なんとかパソコン内の機能だけでObsidianの知識リンクを自動生成してほしい。

この要望に答えるのがdejavuのユーティリティ機能です。  
このようにメモ同士がリンクされて知識化されていくと、dejavuが過去の情報を次々とたどって引き出してくることが可能になり、知識の連想能力が高くなります。

### dejavuがあなたのvaultファイルを変更する唯一の特別な機能

dejavu は自身が書いたメモしか触らないのが鉄則ですが、この機能だけは違います。
**あなたが書いたメモに、dejavu が知識リンクを書き足します。** あなたのメモを直接取り扱うので、実行前の確認、実行後の取り消しなど、何重にもガードをかけてあります。

### どんなときに使うか

パソコンのあちこちに散らばっていた資料を Obsidian に入れたあと、
**メモ内容の近いもの同士をリンクするため**に使います。「これ、前にも似たことを調べた気がする」を探しに行かなくても気づけるようになったり、関連しそうな情報を探しやすくなります。このようなメモ同士の関連性を1件ずつ手でリンクする作業を、あなたに代わってまとめて処理する機能だと思ってください。

### Claude にどう話しかけるか

vault の中にフォルダを作って（たとえば `Inbox`）、資料をまるごと入れます。
そのあと、こう言います。

> 「Inbox に入れた資料に、知識のリンクを作って」

dejavu はまず下調べをして、こう答えます。

> 「42件の資料が見つかりました。内容の近いもの同士を118本のリンクでつなぎます。
> このうち12件はあなたが書いたメモなので、そのファイルが書き換わります。
> あとから元に戻せます。進めますか？」

**「はい」と答えるまで、ファイルは1つも変わりません。**

### 結果の確認

つないだメモを Obsidian で開くと、本文の最後にこんな部分が増えています。

```
## Related

- [[領収書の整理術]]
- [[青色申告の要件]]
```

リンクをクリックすれば、その場でもう一方のメモに飛べます。
Obsidian の**グラフビュー**を開くと、資料同士のつながりが見えてきます。

### リンクを消したい場合

Claude に「さっきのリンクを取り消して」と言えば、**追加したリンク部分だけが消えます。**
リンクを追加した後であなたが書き足した文章は、リンクを消しても残りますので安心してください。

リンクを追加する前のファイルは、パソコン内の別の場所にバックアップしてあります（どこにバックアップしたのか表示します）。

> - この機能には[Ollama](#5-メモ同士を自動でつなぐ任意)を使用します。手順5を済ませてから実行してください
> - あなたのメモがパソコンの外に転送されることはありません。全てパソコン内で処理されます
> - テキストファイル（`.txt`）は`.md` に変換されてからリンク付与されます（変換するかどうか問い合わせあり）
> - 詳しい設定や、うまくいかないときの調べ方は
>   [REFERENCE.ja.md](docs/REFERENCE.ja.md#手持ちの資料をまとめてつなぐ)に書いてあります
